# 목표 레퍼런스 기능 대응안 (현재 API 기준 + 백엔드 갭)

## 1) 결론 요약

- 프론트는 현재 API로 **계층 구조 표시, 접기/펼치기, 상위 목표 달성률 롤업(표시용 계산)** 까지 대응 가능
- 레퍼런스의 핵심 완성도(정합성/협업/권한 흐름)까지 맞추려면 백엔드에
  - **서버 롤업 집계 필드**
  - **승인/참조(approval) 워크플로우**
  - **트리/검색 전용 조회 API**
  가 필요

## 1-1) 레퍼런스 이미지 UI 요소 “전체” 대응 체크리스트

> 기준: 제공된 목록형 화면(좌측 트리 + 우측 조직 패널)의 눈에 보이는 UI 요소를 빠짐없이 분해

| UI 요소 | 현재 상태 | 대응 방식 | 백엔드 필요 |
|---|---|---|---|
| 상단 타이틀 `목표` | 있음 | 유지 | 없음 |
| 탭 `내 목표 / 전체 목표 / 구성원 목표` | 부분 | 현재 owner 필터를 3분기 탭 UI로 변경 가능 | 없음 |
| 상단 액션 `목표 만들기` | 있음 | 유지 | 없음 |
| 우상단 `...` 더보기 | 없음 | 버튼 UI 추가 가능(메뉴는 FE 임시) | 기능 API 필요 가능 |
| 검색 아이콘 버튼 | 부분 | `AppSearchField`를 아이콘 버튼형으로 래핑 가능 | 없음 |
| 필터 아이콘 버튼 | 부분 | 현재 Popover 필터를 아이콘 트리거형으로 변경 가능 | 없음 |
| 범위 토글 `전체` pill | 부분 | 현재 owner/scope control을 pill 스타일로 변경 가능 | 없음 |
| 보조 툴바 `정렬 / 사이클 / 필터 추가` | 부분 | 현재 정렬/필터를 레퍼런스 형태로 재배치 가능 | 없음 |
| 컬럼 헤더 `제목/담당주체/사이클/종료일/진행상태` | 부분 | 리스트 헤더형 UI로 맞춤 가능 | 없음 |
| 트리 expand/collapse caret | 있음 | 유지(현재 구현됨) | 없음 |
| depth 들여쓰기 | 있음 | 유지(현재 구현됨) | 없음 |
| 목표 타입 아이콘(건물/팀/개인 등) | 부분 | ownerType/visibility 기반 아이콘 매핑 가능 | 없음 |
| 진행률 숫자 + 바 + 상태 컬러 | 있음 | 유지/튜닝 가능 | 없음 |
| 상위 목표 롤업 표시 | 있음(프론트 계산) | 유지, 툴팁 안내 | **공식값은 필요** |
| 우측 패널 `조직 검색` | 없음 | UI/상호작용 FE 구현 가능 | 조직-목표 집계 API 권장 |
| 우측 `빠른 선택(전체/팀)` | 없음 | FE 상태로 구현 가능 | 없음 |
| 우측 조직 트리 | 없음 | 조직 데이터가 있으면 FE 트리 렌더 가능 | 조직 트리 API 필요 가능 |
| 우측 조직 선택 시 목록 동기화 | 없음 | FE 필터 가능 | 서버 필터 파라미터 있으면 정합성 향상 |
| 대량 트리 가상스크롤 성능 | 제한적 | FE 최적화 가능 | 서버 트리 조회 API 권장 |
| 목표별 승인 상태 뱃지(레퍼런스 확장 이미지) | 없음 | UI 자리/더미는 가능 | 승인 상태 API 필요 |
| 승인자/참조자 패널(레퍼런스 확장 이미지) | 없음 | UI 스켈레톤 가능 | 승인 워크플로우 API 필수 |
| 활동 내역 타임라인(레퍼런스 확장 이미지) | 부분(실적 기록만) | 목표 활동 탭 추가 가능 | goal activity feed API 필요 |

### 판정

- **“보이는 UI 레이아웃” 자체는 대부분 FE로 재현 가능**
- 하지만 레퍼런스가 의도하는 **데이터 의미(승인 단계, 공식 롤업, 조직 집계 정합성)** 까지 동일하게 하려면 BE 확장이 필수

## 2) 레퍼런스 대비 기능 매핑

### A. 현재 API로 이미 대응 가능한 것

1. 목표 트리 구조
   - 근거: `Goal.parentGoalId` 존재
   - 프론트 처리: 계층 depth 계산/정렬/접기-펼치기 구현 가능

2. 목표 생성 시 상위 목표 지정
   - 근거: `CreateGoalPayload.parentGoalId`
   - 프론트 처리: 생성 모달에서 상위 목표 선택 제공

3. 실적 제출/검토
   - 근거: `POST /goal/{goalId}/performance-record`, `POST /goal/{goalId}/performance-record/{recordId}/review`
   - 프론트 처리: 제출/검토 모달, 목록 무효화 후 재조회

4. 달성률 표시
   - 근거: `Goal.achievementPct`, `actualValue`, `targetValue`, `measureType`
   - 프론트 처리: 서버값 우선 + 계산 fallback 가능

### B. 현재 API로 “부분 대응(프론트 임시 계산)” 가능한 것

1. 상위 목표 달성률 롤업
   - 현 상태: 프론트에서 하위 평균을 계산해 표시 가능
   - 한계:
     - 페이징/필터링 범위 밖 자식이 누락되면 불일치 가능
     - 다른 클라이언트/리포트와 숫자 정합성 차이 발생 가능

2. 트리 기반 정렬/그룹핑
   - 현 상태: 프론트에서 DFS 정렬 가능
   - 한계: 서버 정렬/검색 조건이 복잡해질수록 FE 비용 증가

### C. 백엔드 수정이 필요한 것 (레퍼런스 완성도 핵심)

1. 서버 공식 롤업 집계
   - 필요 이유: 모든 클라이언트에서 동일한 “상위 달성률” 보장
   - 제안:
     - `GET /goal` 응답에 `rolledAchievementPct`, `rollupSource`, `childCount`
     - 또는 기존 `achievementPct`를 서버가 롤업 반영 후 제공

2. 승인/참조 단계 워크플로우
   - 레퍼런스 기능: 우측 패널의 다단계 승인/참조, 반려/승인 액션
   - 필요 데이터 예시:
     - `approvalStatus`, `approvalStep`, `approvers[]`, `watchers[]`, `approvalHistories[]`
   - 필요 API 예시:
     - `POST /goal/{id}/approval/request`
     - `POST /goal/{id}/approval/{approvalId}/approve|reject`
     - `GET /goal/{id}/approval`

3. 트리 조회 전용 API
   - 필요 이유: 대량 데이터에서 FE 트리 조립/검색 성능 및 정합성 확보
   - 제안:
     - `GET /goal/tree?scope=&owner=&orgId=&period=`
     - 노드별 `childrenCount`, `hasChildren`, `path`(breadcrumb) 포함

4. 조직/담당 기반 탐색 고도화
   - 레퍼런스 우측 조직 패널 수준 구현 시 필요
   - 제안:
     - `GET /goal?orgId=&ownerId=&includeDescendants=true`
     - 집계 반환: `countByOrg`, `countByStatus`

## 3) 전/후 시나리오 (AS-IS → TO-BE)

## 시나리오 1: 상위 목표 진행률 확인

- AS-IS
  1) 사용자가 목표 목록 진입
  2) 상위 목표 진행률이 목표 자체 값/계산으로 보이거나, FE 임시 롤업 계산으로 표시
  3) 필터/범위에 따라 상위 수치가 달라질 수 있음

- TO-BE
  1) 사용자가 목록 진입
  2) 서버가 계산한 `rolledAchievementPct`를 상위 목표에 제공
  3) 어디서 보든 동일한 상위 진행률 보장

## 시나리오 2: 하위 목표 실적 제출 후 상위 자동 반영

- AS-IS
  1) 하위 목표 실적 제출/검토
  2) 해당 목표 `actualValue/achievementPct` 업데이트
  3) 상위 목표는 FE에서 재계산 표시(공식값 아님)

- TO-BE
  1) 하위 목표 실적 제출/검토
  2) 서버 트랜잭션 내 상위 체인 롤업 재집계
  3) 목록 재조회 시 상/하위 모두 공식 집계값 반영

## 시나리오 3: 목표 생성 승인 요청

- AS-IS
  1) 목표 생성
  2) 즉시 목록 반영 (별도 승인 상태 없음)

- TO-BE
  1) 목표 생성 후 `DRAFT` + `approvalStatus=PENDING`
  2) 승인자에게 할당/알림
  3) 승인 완료 시 `ACTIVE` 전환, 반려 시 사유 기록

## 시나리오 4: 사이드 패널 승인/활동 히스토리 조회

- AS-IS
  1) 목표 상세에서 기본 정보/실적 기록 중심 조회
  2) 승인 단계/참조자 타임라인 데이터 부재

- TO-BE
  1) 목표 상세 진입 시 approval + activity feed 조회
  2) 단계별 승인자 상태(대기/승인/반려), 코멘트, 시간 노출

## 4) 권장 구현 순서

1. **Phase 1 (현재 API 기반 FE 완성)**
   - 트리 UX(접기/펼치기/깊이 정렬), 롤업 표시(프론트 계산), 툴팁 안내

2. **Phase 2 (BE 집계 계약 확정)**
   - 롤업 정책 확정: 직속 평균 vs 가중 평균(`weightPct`) vs 목표값 비율 기반
   - 응답 필드 확정: `rolledAchievementPct` 등

3. **Phase 3 (승인 워크플로우)**
   - 승인 엔티티/상태머신/API + 프론트 승인 패널 연동

4. **Phase 4 (트리/검색 API 최적화)**
   - 대용량 조직 기준 조회/집계 endpoint 분리

---

## 5) 백엔드에 바로 전달할 최소 요청사항

1. 목표 조회 응답에 상위 공식 집계 필드 추가
   - `rolledAchievementPct: number | null`
   - `rollupSource: 'SELF' | 'CHILDREN_AVG' | 'CHILDREN_WEIGHTED'`
   - `childCount: number`

2. 실적 제출/검토 시 상위 체인 재집계 보장
   - 같은 트랜잭션에서 부모까지 업데이트

3. 승인 워크플로우 기본 API
   - 요청/승인/반려/조회 + 이력

4. 트리 조회 API
   - 계층/조직/기간 필터를 서버에서 일관 처리
